# Client routing rules

This page covers the **routing rules inside the client profile**: why they are needed, how the layers are ordered, how to add or remove domains, and how to verify that a domain really goes direct.

The server side does not route client traffic. `templates/singbox/03_route.json` sets `final` to `direct` (unless `--with-warp` adds selective server-side rules) — the node forwards traffic out. **Client-side split-tunneling happens in the client profile** that the subscription server hands out (`profile.json` / `profile.yaml`, with `profile.txt` providing multi-path URIs for URI-based apps).

---

## Why routing rules are mandatory

In **system-proxy** mode, missing rules only cost you latency: local and regional sites hairpin across a trans-oceanic gateway but still load.

In **TUN virtual-NIC mode** — the default for the sing-box official apps, Karing, and Hiddify — the kernel hijacks all traffic and there is **no "global / direct" toggle: whether a flow is proxied is decided entirely by the rules**. With incomplete rules:

- Local and regional services (banking apps, e-commerce, messaging) get sent across a trans-oceanic gateway — slow, CAPTCHA-heavy, and some banks reject distant IPs outright
- Regional DNS queries are resolved at the remote gateway, so regional CDNs return far-away edges and everything slows down
- Ad and tracker domains still resolve and connect, burning node bandwidth

So the profiles this project generates **ship with complete routing rules by default**. Import and go; no manual configuration required.

---

## The four-layer rule stack

The `route.rules` generated by `scripts/build_profile.py` are evaluated top-down, **first match wins**:

```
Layer 0  Baseline actions & WebRTC STUN guard
  ├─ sniff                        protocol sniffing, recover the real domain
  ├─ protocol=dns → hijack-dns    hand DNS queries to the built-in DNS module
  ├─ STUN / WebRTC leak guard     block public STUN (unless --allow-webrtc / ?allow_webrtc=1)
  └─ ip_is_private → direct       LAN / private ranges bypass the proxy

Layer 1  Ad blocking
  └─ rule_set geosite-category-ads-all → reject

Layer 2  Regional split-tunneling / local direct bypass (two tiers)
  ├─ explicit domain_suffix safety net (REGIONAL_SAFETY_NET) → direct  ← hand-curated, inline
  ├─ rule_set geosite-cn (APAC regional rule-set example)    → direct  ← SagerNet community set, inline
  └─ rule_set geoip-cn (APAC regional rule-set example)      → direct  ← SagerNet community set, inline

Layer 3  Fallback
  ├─ udp:443 → reject             block HTTP/3 QUIC so browsers fall back immediately to TCP
  └─ final   → node outbound
```

### Why Layer 2 has two tiers (and zero boot-time downloads)

| | Inline `REGIONAL_SAFETY_NET` | `geosite-cn` / `geoip-cn` rule-sets |
|---|---|---|
| Contents | ~60 hand-picked high-frequency regional suffixes | tens of thousands, community-maintained |
| Visibility | plain JSON in `route.rules` / `dns.rules` | compiled as `type: inline` in `profile.json` |
| Source | `REGIONAL_SAFETY_NET` in `scripts/build_profile.py` | pre-fetched weekly on the server (`refresh-rulesets.timer`) |
| Failure mode | none | zero client startup network requests (eliminates cold-start deadlocks) |

`geosite-cn` and `geoip-cn` ship as the default **APAC regional rule-set example** so local ISP and regional CDN traffic stays on the physical interface with local DNS rather than hairpinning across a trans-oceanic gateway; they can be customized or removed for any region. Because all rule-sets are compiled into `profile.json` as `type: inline` on the server (see [Multi-Path Transport & WAN Tuning](MULTIPATH-TRANSPORT.md)), clients perform zero network requests at startup.

`REGIONAL_SAFETY_NET` adds a ~60-entry explicit domain-suffix tier right ahead of the rule-sets so high-frequency banking, messaging, and media services stay direct even in minimal or hand-trimmed profiles.

## Adding or removing domains

**Change the template (applies to all future installs):**

```bash
# 1. Add a line to the domain_suffix array, e.g. "newplatform.com"
vim scripts/build_profile.py          # or data/geosite-cn-extra.json

# 2. Regenerate examples and run the gates — examples/ is drift-checked in CI
make examples
make lint test
```

**Change a live server (applies to existing users immediately):**

```bash
# This is the file the subscription server hands out
vim /etc/anyreality-resi-stack/files/profile.json

# Always validate before letting clients pull it
sing-box check -c /etc/anyreality-resi-stack/files/profile.json
```

Clients pick up the change on their next subscription refresh (24h by default, controlled by the `Profile-Update-Interval` header / `UPDATE_INTERVAL_HOURS`). Hit refresh in the client to apply it now.

## Verifying that a domain goes direct

**Do not judge egress with a bare `curl` on a machine running a TUN client.** TUN hijacks the route and `HTTP_PROXY` intercepts on top of that, so a "success" may have exited through an entirely different proxy. The result is meaningless.

```bash
# 1. Bypass the env proxy AND pin the physical interface
curl --noproxy '*' --interface en0 -sI https://www.163.com | head -3

# 2. Read which outbound the client actually chose (set log.level to info first)
journalctl -u sing-box -f | grep 163.com              # Linux
tail -f ~/Library/Logs/sing-box.log | grep 163.com    # macOS

# 3. Confirm the proxied egress IP is your node
curl -x socks5h://127.0.0.1:2080 https://checkip.amazonaws.com
```

## Changing the defaults

| Goal | Edit |
|---|---|
| Disable ad blocking | Remove the `geosite-category-ads-all` `reject` rule |
| Allow QUIC / HTTP/3 | Remove `{"network":"udp","port":443,"action":"reject"}` |
| Tunnel all traffic without regional bypass (other regions) | Remove or replace the three Layer 2 `direct` rules and customize `REGIONAL_SAFETY_NET` |
| Use a different local/regional DNS | Change `dns-direct`'s `server` in `dns.servers` (default `223.5.5.5`, or set local ISP / `1.1.1.1`) |
| Switch to TUN mode | Replace the `mixed` inbound with `tun`; prefer `"stack": "system"` — `gvisor`/`mixed` spam socket errors on some macOS clients |
| Dual-node split routing | See [Dual-node smart routing](DUAL-NODE.md) |

Always run `sing-box check -c <file>` after editing, and only publish a profile that passes.

## What changes in dual-node mode

`--with-aggregator` serves dual-node profiles via `scripts/build_profile.py`. The layers are identical, with two extra groups inserted between Layer 2 and Layer 3:

```
Layer 2.5  Per-service egress selection
  ├─ OpenAI / Anthropic / Gemini / Netflix domains → residential node
  ├─ Telegram / Discord domains                    → data-center node
  └─ Telegram IP ranges (91.108.x, 149.154.160.0/20) → data-center node
```

Order matters: **Regional split-tunneling comes first, service selection second**, so local/regional domains stay on the physical interface with local DNS rather than hairpinning across a trans-oceanic gateway. See [Dual-node smart routing](DUAL-NODE.md).
